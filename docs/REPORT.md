# 実装・検証レポート

作成日：2026-11-13

## 1. 前提と仕様上の判断

受け取った仕様書は 15章の途中〜19章のみで、1〜14章（画面仕様・データ項目・ゲームバランスなど）は手元にありませんでした。
そのため、15〜19章に書かれた必須要件を満たすことを優先し、書かれていない部分は次のとおり判断して実装しています。
前半の仕様と食い違う箇所があれば、`src/lib/game.ts` の定数や各画面を調整してください。

| 項目 | 仕様書に明記 | 今回の判断 |
| --- | --- | --- |
| Next.js / TypeScript / IndexedDB / 単体・E2E テスト / レスポンシブ | あり | そのまま採用 |
| タスクの追加・編集・削除・完了、報酬、エサやり、成長 | あり | そのまま実装 |
| 画面構成 | なし | ホーム／タスク／きろく／せってい の4画面 |
| タスクの項目 | なし | タイトル（必須・60字）、メモ（200字）、むずかしさ3段階、期限（任意） |
| 報酬の決め方 | なし | むずかしさごとに別のエサを1つ。1タスク1回まで |
| 成長の仕組み | なし | XP→レベル→4段階の姿。満腹度は時間で減少し表情に反映 |
| ねこの素材 | 「画像・アニメーション素材」 | 自作 SVG コンポーネント＋CSS アニメーション（画像ファイルは使わない） |
| 追加した機能 | なし | 初回の名付け、なでる、きろく、バックアップ／復元、リセット |

### 開発中に行った仕様変更

| 変更 | 理由 |
| --- | --- |
| 報酬受け取り後は、むずかしさを変更不可にした | 受け取ったエサとタスクの内容が食い違わないようにするため |
| 初期状態でカリカリを1つ配布 | タスクを作る前でも「エサやり」を一度体験できるようにするため |
| TypeScript は最新の 7.0 ではなく 6.0 を採用 | Next.js 16 のビルド時型チェックとの相性を確認できていないため |
| E2E は既存サーバーを再利用しない設定にした | 開発中、古いビルドのサーバーに対してテストが走り、修正が反映されない事象があったため |

### セキュリティ・動作の検証（2026-11-14）

| 観点 | 結果 | 対応 |
| --- | --- | --- |
| 依存ライブラリの既知の脆弱性（`npm audit`） | 0件（本番・開発とも） | なし |
| 危険な書き方（`dangerouslySetInnerHTML`・`eval`・`innerHTML` など） | なし。React が文字として表示する | E2E で HTML 入りのタスク名が実行されないことを確認 |
| 秘密情報の混入 | なし | なし |
| HTTP セキュリティヘッダー | **未設定だった** | CSP（外部スクリプト・外部通信・iframe 埋め込みを禁止）、X-Content-Type-Options、X-Frame-Options、Referrer-Policy、Permissions-Policy、COOP を追加。X-Powered-By を削除 |
| 細工したバックアップ | **XP を極端に大きくすると、レベル計算が終わらず画面が固まった** | レベル計算を式に変更し、XP・個数・日時・件数・ID 長に上限を設定。`__proto__` などの余計なキーは取り込まない |
| 壊れた・大きすぎるファイル | 拒否される（5MB まで） | E2E を追加 |
| 連打（完了・エサ） | 二重にならない（1トランザクション内で確認している） | E2E を追加 |
| 複数タブで同時に使う | **片方の操作がもう片方に反映されず、表示が古いままだった**（データは壊れない） | BroadcastChannel で変更を通知し、タブに戻ったときも読み直す |
| IndexedDB が使えない環境 | 説明つきのエラー画面が出る | E2E を追加 |
| 開発サーバー（CSP 適用後） | エラーなし | 開発時のみ `unsafe-eval` と WebSocket を許可 |
| 初回表示の通信量 | 約 1.4MB（圧縮前）。フォント 409KB・JS 540KB・CSS 334KB・ねこ写真 103KB | 改善候補として記録 |

CSP の `script-src` は、Next.js が出力するインラインスクリプトのため `'unsafe-inline'` を含みます。外部から HTML を差し込む経路はないため、外部スクリプトの読み込み禁止を優先しました。nonce 方式にするとページが静的生成でなくなるため見送っています。

### 脆弱性診断・侵入テスト（2026-11-14）

対象は本番ビルド（`next start`、ローカル）。サーバー側は curl、ブラウザ側は Playwright（`scripts/pentest.mjs`）で実施。

**見つかった問題と対応**

| 重要度 | 内容 | 対応 |
| --- | --- | --- |
| 中 | 保存データ（IndexedDB）の中身が想定外の形だと画面が真っ白になり、アプリ内から復旧できない（6パターン中5パターンで再現） | 読み込み時に必ず検査・補正する処理（`sanitizeState` / `sanitizeTask` / `sanitizeEvent`）を追加。描画エラー時の復旧画面（`src/app/error.tsx`：再試行・バックアップ保存・リセット）を追加 |
| 低 | 使っていない画像変換の入口（`/_next/image`）が開いていた（外部URL・ローカルファイルの取得は拒否されるが、変換処理でCPUを使わせられる） | `images.unoptimized` で無効化（404 になることを確認） |
| 低 | タスク名・名前に、文字の並び順を変える不可視文字や改行を入れられた（表示の偽装） | 保存時と読み込み時に取り除く |

**試して成立しなかった攻撃**

| 分類 | 内容 |
| --- | --- |
| ファイルの露出 | パス操作（`../`・`%2e%2e`・`%2f`）、`.env`・`.git`・`package.json`・ソース・ソースマップの取得 → すべて 404 |
| Next.js 固有 | 画像変換でのSSRF（外部URL・メタデータIP・`file://`）、サーバーアクションの偽リクエスト、ミドルウェア回避ヘッダー → 拒否 |
| ヘッダー・リダイレクト | Host / X-Forwarded-Host の書き換え、`//evil.example` 形式のリダイレクト、改行によるヘッダー注入、URL への HTML 埋め込み → 反映されない |
| HTTP | GET/HEAD 以外は 405、長大な URL・ヘッダーは 431、Cookie なし、CORS ヘッダーなし |
| XSS | 10種の文字列 × タスク名・メモ・名前、およびバックアップ経由（名前・ID・タイトル・メモ・履歴）→ 実行されない |
| 埋め込み | 別サイトの iframe への埋め込み → `frame-ancestors` で拒否 |
| 外部送信 | 外部スクリプト・fetch・画像URL・sendBeacon・フォーム送信・eval → CSP で拒否 |
| 負荷 | 上限いっぱいのバックアップ（5000タスク・2万履歴）、20万段の入れ子JSON → 落ちない |
| 供給網 | レジストリ署名 69件すべて検証済み、取得元は npm 公式のみ、本番依存にインストール時スクリプトなし、git 履歴に秘密情報なし |

**残るリスク（未対応）**

- CSP がページ内スクリプトの実行を許可している（`'unsafe-inline'`）。XSS が成立した場合の最後の防壁が弱い。nonce 方式にすると全ページが動的生成になるため見送り
- レスポンスに `x-nextjs-cache` などの内部ヘッダーが出る（使用技術が分かる程度）
- 5000件のタスクでタスク画面の表示に約5秒かかる（一覧の仮想化をしていない）
- 公開先のサーバー・TLS・DNS の設定は診断対象外（デプロイ先が未定のため）
- 診断はツールによる自動実行と目視で、第三者による診断ではない

### UI崩れの修正（2026-11-15）

320〜1920px の10種類の幅で全画面を撮影し、はみ出し・重なり・文字切れを機械的に検出（`scripts/ui-check.mjs`）したうえで目視確認した。

| 幅 | 崩れ | 対応 |
| --- | --- | --- |
| 320〜360px | ホームの「タスクを追加」ボタン、タスク画面のむずかしさ説明・絞り込みが画面外にはみ出し、横スクロールが出ていた | 小さいスマホ用の余白・文字サイズを追加。見出しを折り返せるようにし、ボタン文言を「追加」に短縮 |
| 900〜1099px | サイドバーが出る幅で本文が狭くなり、統計タイルの文字が1〜2文字ずつ折り返していた | サイドバーへの切り替えを 1024px からに変更 |
| 1100〜1499px | 2カラムの部屋カードが狭く、「ごちそう缶」が折り返し、ふきだしがねこに重なっていた | この幅では部屋カードの中身を縦積みにし、横並びは 1500px 以上に限定 |
| 全幅 | 王冠が大きすぎて頭からはみ出していた／育成メモの肉球の飾りが本文に重なっていた | 王冠を小さくして耳のあいだに配置／飾りを見出しの右上へ移動 |
| PC 全般 | 背景を画面固定（`fixed`）にしていたため、iOS Safari や長いページで下部が白く抜けうる | 背景色を下地にして固定指定をやめた |

### 単体テストの対象

- レベル・成長段階の境界値、満腹度の減衰と上下限、きげんの区分
- 報酬の付与、エサやり（在庫なしの拒否、レベルアップ・成長の検出、満腹度の上限）
- 連続日数の計算、入力検証（空・文字数超過・不正な日付）
- データ層：初期化、タスク CRUD、完了時の報酬と履歴、二重取り防止、在庫なし時に状態が変わらないこと、エクスポート→リセット→インポートの往復、壊れたバックアップの拒否

### E2E シナリオ

1. 初回起動で名前をつける（空欄は拒否）
2. タスク追加→完了→エサ獲得→エサやり→レベルアップ→リロード後も保持
3. タスクの追加・編集・完了・戻す・削除、再完了で報酬が増えないこと
4. きろくへの反映、名前変更、リセット
5. バックアップの保存、壊れたファイルの拒否、復元
6. 4画面で横スクロールが発生しないこと

### 検証中に見つけて修正した不具合

| 不具合 | 対応 |
| --- | --- |
| リセット後の名付け画面に、前回の名前が残る | 名付け完了時に入力をクリア（E2E に確認を追加） |
| タブレット幅で部屋のイラストが隣のカードに重なる | CSS の上書き順を修正 |
| 空腹時の表情が怒っているように見える | まゆの向きを「ハの字」に修正 |
| ねこさまの王冠とふきだしが重なる | ねこのサイズとふきだしの位置を調整 |
| スマホでエサをあげても、ねこが画面外で見えないことがある | エサやり時に部屋までスクロール |
